# 开发日志 · 2026-09-29

> 范围：v1.1.0 → v1.2.0 → v1.2.1 → v1.3.0（同一天内四个版本）
> 测试环境：Oracle Cloud Ampere A1（ARM64 Neoverse-N1，4 核 / 24 GB，Ubuntu 26.04），Xray 26.2.6，sing-box 1.14.2
> 原则：每项改动都先在真机上复现 / 测量，再修复，再用同样方法验证；没有测量收益的优化不合入。

---

## 0. 背景与方向

- 面板定位：一体化工具箱，但**核心是高性能、稳定地提供 VPN 服务，以及准确的流量统计与监控**；其他功能锦上添花，必须控制对 VPS 的资源开销。
- 部署：新 VPS 仅允许 SSH 密钥登录；面板管理端口不对公网开放（通过 SSH 隧道访问）。

## 1. v1.1.0 — ARM64 支持与安全加固

| 问题 | 根因 | 修复 |
|---|---|---|
| ARM 服务器无法运行镜像 | Dockerfile 写死 `GOARCH=amd64` 及 amd64 版 Xray / sing-box | 多架构构建（`TARGETARCH`），CI 同时发布 amd64 + arm64；注意 stage 内 `ARG TARGETARCH=amd64` 的默认值会覆盖 BuildKit 自动值，已去掉默认值 |
| **严重：安装向导登录绕过** | 设置完成并重启后一次性口令为空串，`POST /api/setup/login {"password":""}` 可拿到等同管理员的 JWT | 设置完成后向导接口返回 404；完成时清空口令；向导 JWT 不能访问 `/api/v1` |
| API Token 权限范围形同虚设 | 仅 5 个路由检查 scope | 统一的 scope 中间件（终端 / 文件 / cron / admin 需 `admin`） |
| 伪造 `X-Forwarded-For` 绕过白名单与登录锁定 | gin 默认信任所有代理 | 默认不信任，`ZENITH_TRUSTED_PROXIES` 显式开启 |
| 面板添加的防火墙规则无效 | `iptables -A` 追加在 Oracle 镜像的兜底 REJECT 之后 | 插入到兜底 REJECT/DROP 之前；删除规则时带上 comment 匹配 |
| sing-box 因限速 / 端口段配置启动失败 | 生成了不存在的字段、端口段格式错误 | 用真实二进制 `sing-box check` 复现并修复 |
| 一键安装脚本不可用 | 依赖从未发布的 release 压缩包 | 改为部署 Docker 镜像 |

## 2. v1.2.0 — 按 CPU 优化

实测（Neoverse-N1 单核，16 KB AEAD）：

| | AES-128-GCM | AES-256-GCM | ChaCha20-Poly1305 |
|---|---|---|---|
| 有 AES 硬件 | **2533 MB/s** | 2057 MB/s | 485 MB/s |
| 屏蔽 AES 硬件 | 90 MB/s | 77 MB/s | **485 MB/s** |

- 新增 CPU 识别（Intel / AMD / Arm Neoverse / AmpereOne / 鲲鹏、AES/PMULL、AVX2/512、SVE、LSE、虚拟机屏蔽 AES-NI）。
- 结论：TLS/QUIC 类协议（Reality、Hy2、TUIC、Trojan）由 Go TLS 自动按 CPU 选择套件；**SS-2022 多用户模式在 Xray 与 sing-box 中都只支持 AES**（实测确认），所以无 AES 硬件时建议改用 Reality/Hy2/TUIC，并在 Smart Deploy 中提示。
- RPS/RFS：网卡接收队列少于 CPU 核数时（本机 2 队列 / 4 核）把收包处理分摊到所有核，可回滚。
- 修复：Docker 部署中 Smart Deploy 的内核调优在宿主机重启后全部丢失（sysctl 文件在容器内），现启动时自动重新应用。
- **未采纳（有测量）**：引擎 `GOGC=200` 实测 CPU 仅变化 ~2%（噪声内）；`GOAMD64=v3` / `GOARM64=v8.2` 收益小且会在老 CPU / 模拟 CPU 上无法运行。

## 3. v1.2.1 — Reality 默认目标无法通流量

- 现象：节点端口正常、面板测试 ✓，但客户端完全无法使用。
- 排查：服务端日志 `REALITY: handshake did not complete successfully`；矩阵测试（目标 × 指纹）显示 `www.microsoft.com` 全部失败，`www.apple.com` / `www.cloudflare.com` / `dl.google.com` 全部成功。
- 修复：默认目标改为 `www.apple.com`（Smart Deploy、快速设置、编辑器、文档、脚本）。
- 附带经验：本机网络存在 TUN 代理会伪造所有 TCP 连接并按 SNI 改路由，外部连通性测试需改用 check-host.net + 服务器端 iptables 计数器；OCI 安全列表的「源端口范围」必须留空。

## 4. v1.3.0 — 可靠性、流量统计准确性、sing-box 1.14

### 4.1 端到端自检（`proxy test`）
- 旧测试只检查端口是否监听，正是 v1.2.1 问题被漏掉的原因。
- 新实现：取节点第一个启用用户的**真实订阅链接** → 转换为 sing-box 客户端 → 连接 127.0.0.1（TLS 名称保持公网地址）→ 访问 Cloudflare trace，报告出口 IP 与延迟。
- 反向验证：临时创建目标为 microsoft 的节点，旧测试 ✓，新测试 ✗ `stage=proxy`。
- 自检过程中顺带发现并修复两个真实缺陷：
  - Smart Deploy 自签证书的 Hy2/TUIC 节点，分享链接缺少 `insecure=1` / SNI（订阅生成器不认 sing-box 原生 `tls` 结构）→ 所有客户端证书校验失败。
  - Smart Deploy 节点未保存公网地址，通过 SSH 隧道访问面板时二维码里是 `127.0.0.1`。

### 4.2 公网订阅访问
- 问题：订阅链接使用面板地址，面板走 SSH 隧道时手机根本拉不到订阅。
- 新增独立订阅端口（默认 2096），只响应 `/<随机密钥>/<uuid>`，有证书时自动 HTTPS，不信任 XFF；开启时自动放行宿主机防火墙。
- 面板启动 / 每次应用配置后，自动确保已启用节点端口和订阅端口在「默认拒绝」的防火墙中放行（容器内添加的 iptables 规则在宿主机重启后会丢失）。

### 4.3 空闲开销
- 实测：无人查看时面板占用 **2.8%** CPU（每 5 秒全进程扫描、每 2 秒全表查询、每 10 秒 4 次 `ss`、未缓存的设置读取）。
- 改为「有人查看才做 UI 专用采样」、设置读取 3 秒缓存、`ss` 监听端口缓存 60 秒。
- 结果：**0.05%** CPU，RSS 39 MB → 29.5 MB；打开页面时立即刷新完整数据。

### 4.4 流量统计准确性（重点）
| 问题 | 影响 | 修复 | 验证 |
|---|---|---|---|
| Xray v26 统计值由字符串变为 JSON 数字，解析整体失败 | **所有 Xray 用户流量一直为 0** | 同时接受两种格式 | 100 MB 下载计入 105,155,250 B（+0.28% 协议开销） |
| sing-box Clash API 连接信息不含用户 | **Hy2/TUIC 用户流量一直为 0** | 每个用户一个 `user:<身份>` direct 出站，从连接的出站链识别用户 | 流量只计入正确用户 |
| 连接在两次轮询之间关闭，其字节丢失 | 高速下载时约 60% 未计 | 用 Clash 全局累计差值补回，按消失连接的最近速率分配 | 3×100 MB 计入 315,463,737 B（+0.28%） |
| 同一邮箱存在于多个入站，按邮箱更新 | 同一流量被重复计入多行 | 引擎使用唯一身份（重复时 `email#id`），按 ID 写库 | 仅正确行增加 |
| Xray 使用 `-reset` 读取 | 写库失败即丢失 | 读取累计值自行做差，失败重试；按引擎启动时间识别重置 | 单测覆盖 |
| 应用配置总是重启两个引擎 | 所有用户断线；Xray 未关闭连接的字节丢失 | 配置未变化的引擎保持运行（`?force=1` 可强制） | 下载过程中应用配置，下载不中断且完整计费 |

- 说明：Xray 只在连接**关闭时**才把字节计入用户计数器，所以统计会滞后一个连接，但不会丢失（除非引擎被强制重启）。

### 4.5 sing-box 1.11.0 → 1.14.2
- 迁移：`block`/`dns` 特殊出站 → `reject` / `hijack-dns` 规则动作；WireGuard 出站 → `endpoints`（同时修复 WARP 地址缺少 `/32`、`reserved` 为十六进制字符串两个旧 bug）；DNS 改为类型化服务器；新增 `default_domain_resolver`（优先 IPv4）。
- 镜像改用 `-musl` 版本（1.12 起普通压缩包依赖 glibc，在 Alpine 上 exit 127）。
- 验证：`sing-box check` 通过（含 reject 规则 + WireGuard endpoint）；VLESS / Hy2 / TUIC 端到端全部通过，出口均为 IPv4 `129.146.187.122`。

### 4.6 其他
- 删除的节点 / 用户无法以同名重建（软删除占用唯一索引）→ 改为硬删除并在启动时清理历史软删除记录。
- 审计日志异步写入的数据竞争（`-race` 发现）。
- 清理测试环境时发现：Smart Deploy 回滚只删了入站（软删除），用户残留成孤儿 → 回滚改为硬删除入站及其用户，启动时清理孤儿用户。
- 面板为已删除 / 停用节点打开的端口一直不关闭 → 面板只清理自己添加的（注释 `zenith-*`）且已无节点使用的规则，手动规则不动。实测关闭了 2 个残留 UDP 端口。
- 单用户限速：两个引擎都不支持按用户限速，界面上的设置从未生效 → 移除该选项（字段保留以兼容备份）。
- 出口 IP 偏好：核查后确认 Xray 已是 `UseIPv4v6`、sing-box 已 `prefer_ipv4`，无需改动（此前的 IPv6 出口来自手写测试配置，是误判）。

## 5. 已知限制 / 后续

- 通过用户路由规则走 WARP 等非 direct 出站的 sing-box 流量，无法按用户细分（仍计入全局，但不归属用户）。
- 单用户限速需要自编译带 `with_v2ray_api` 的 sing-box 或内核级方案，暂不做。
- 订阅端口无证书时为明文 HTTP（界面有警告）；推荐使用 `<ip>.nip.io` + ACME 签发证书（需放行 80 端口）。

## 6. 验证方式汇总

- 单元测试：`go test -race ./...`、`golangci-lint v2.6.2`、前端 `vue-tsc` 构建与 `node --test`。
- 真机：在 ARM64 VPS 上本地构建镜像并部署；VLESS / Hy2 / TUIC 实际下载测速与计费对账；模拟宿主机重启（删除 iptables 规则、重置内核参数后重启容器）；外部可达性用 check-host.net 并以 22 端口为对照。
